# MAGI UI-D1 信息架构提案摘要

本阶段只确认用户流程与信息位置，不冻结最终视觉风格。

提议采用“决策收件箱 + 单个版本化决策工作区”的结构。工作区包含五个区域：

1. 概览：问题、选项、约束、未知项、风险、状态和当前操作；
2. 证据：来源、验证状态、分类、时间、哈希和引用关系；
3. 三人格观点：安全展示进度、首轮观点、最终票和复议理由；
4. 最终报告：结论、票数、多数理由、少数意见、风险与下一步；
5. 审计与版本：公开事件、版本关系、比较和导出。

创建后必须单独确认标准化结果，确认后仍需显式点击运行。首轮投票期间不展示
任何票；交叉评审期间只能展示已经释放并明确标注为“非最终”的首轮票；仲裁后
才能展示最终票和报告。

UI-D1 同时识别出正式客户端的后端前置缺口：授权决策列表、冻结前编辑、新版本、
事件回放、权限能力发现，以及 M4 的证据与审计接口。接口不存在时不使用假功能。

进入 UI-D2 前需要确认五项决定：总体结构、五个工作区区域、确认与运行分离、
交叉评审期间的首轮票展示方式，以及当前深色页面仅作为视觉参考。
