# MAGI UI-D4b-2a 异步操作契约

状态：已采用；契约模型和 PostgreSQL 存储已实现，接口和工作器尚未激活。

## 提案结论

创建决策和运行 MAGI 不再依赖一个浏览器 HTTP 连接长时间保持。客户端使用
`Prefer: respond-async` 显式请求异步执行，服务器将命令持久化后返回 `202 Accepted`
和操作回执。旧的同步调用保留兼容，服务器不会暗中改变执行模式。

## 客户端能看到什么

- 状态：`accepted`、`running`、`succeeded`、`failed`。
- 阶段：排队、协调器、第一轮、交叉复核、仲裁、报告、完成。
- 事件：已接受、已开始、阶段变更、成功、失败。
- 没有虚假百分比，不显示模型重试次数、部分投票、提示词或私有推理。
- 成功后再读取权威 `DecisionView`，不把事件当作结果。

## 为什么必须保存请求内容

异步创建需要在 HTTP 结束后把原始问题和证据交给 Coordinator。只保存哈希无法恢复输入，
因此请求 JSON 必须按决策数据级别保护、限期保留。令牌、原始主体标识和原始幂等键不入库。

## 工作器恢复

- PostgreSQL `SKIP LOCKED` 领取任务。
- 租约记录可观测活性，会话级 advisory lock 防止两个工作器同时执行。
- fencing 次数防止旧工作器覆盖新结果。
- Coordinator 调用、LangGraph 检查点和模型调用账本继续提供效果幂等。

## 请确认的 6 项

1. 采用 `Prefer: respond-async`，同时保留同步兼容。
2. 采用持久化轮询回执和游标事件回放，SSE 仅作未来优化。
3. 采用四状态、七阶段，不显示百分比。
4. 允许将异步请求 JSON 按决策数据等级受控保存。
5. 采用租约＋advisory lock＋fencing 的工作器规则。
6. 操作取消不纳入本增量。
