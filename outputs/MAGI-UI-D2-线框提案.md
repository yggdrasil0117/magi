# MAGI UI-D2 线框提案

状态：待确认。确认后进入 UI-D3 高保真视觉基础。

## 本轮已落实

- UI-D1 的 1–5 项决策已全部采用：决策收件箱、版本化工作区、五个分区、
  确认与运行分离、交叉复核期只显示已释放的第一轮临时意见。
- Web 采用“左侧决策索引＋中央工作区＋右侧三方诊断”的宽屏架构。
- 窄屏依次收敛为状态、内容、三方诊断、操作门，不缩小成无法阅读的密集面板。
- 终端在 120 列以上使用双窗格，80–119 列收起导航，80 列以下完全纵向排列。
- 所有改变状态的操作都先呈现后果，再要求第二次明确确认。

## EVA / NERV 素材方案

界面已为顶部 NERV 标志、右侧截图或参考画面、角色背景图和装饰性口号预留替换位。

当前不将官方文件提交到仓库。每个素材需要记录来源、权利人、许可或授权编号、
适用媒介、地区、期限、是否允许改作、署名和文件哈希。未完成记录时，开发版显示
中性占位，发布版拒绝打包。即使全部不使用，界面也保持完整可用。

## 可直接查看的成果

使用浏览器直接打开 `apps/web/wireframes/ui-d2.html`，可在决策收件箱、确认与冻结、运行门、
交叉复核、最终报告、降级与恢复六个场景之间切换。原型只使用虚构数据，不调用 API，
不会被生产 Web 服务器发布。

## 请确认的 6 项

1. 采用 Web 宽屏三分区与移动端单列顺序。
2. 采用概览、证据、三方观点、报告、审计的持久导航。
3. 采用“状态说明在前、主内容在中、操作门在后”的顺序。
4. 采用三视角等权显示，交叉复核时反复标明“第一轮——临时、非最终”。
5. 采用可选授权素材位，并保留完整原创回退界面。
6. 采用终端三档宽度和“变更状态前二次确认”的键盘行为。

回复“UI-D2 采用”即可冻结这 6 项，然后进入 UI-D3。
