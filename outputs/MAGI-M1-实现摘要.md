# MAGI M1 实现摘要

状态：已实现  
项目版本：0.1.0  
协议版本：1.0  
架构版本：0.2

## 已实现

- Pydantic 不可变领域模型
- 决策生命周期状态机
- 第一轮确定性路由
- 最终确定性仲裁器
- 少数派报告
- 硬性约束验证结果
- 决策与证据版本一致性检查
- 证据引用完整性检查
- Restricted 证据引用拦截
- 重复 Agent 选票拦截
- 版本化 JSON 测试夹具

## 仲裁行为

- 低或中风险 3:0：共识
- 高风险 3:0：要求交叉审查
- 第一轮 2:1：要求交叉审查
- 第一轮 1:1:1：要求交叉审查
- 第二轮 2:1：多数决并保存少数派报告
- 第二轮 1:1:1：未形成结论
- 两个人格弃权：信息不足
- 一个人格不可用：降级，只能作为参考
- 两个人格不可用：失败
- 已接受的硬性约束：有条件否决
- 置信度：仅记录，不参与票数加权

## 安全与完整性

- 未经用户确认的决策单不能进入投票。
- 证据快照必须匹配决策 ID 和版本。
- 选票只能引用冻结快照中存在的证据。
- 选票不能引用 Restricted 证据。
- 一个 Agent 在同一轮只能有一张有效票。
- 第二轮选票必须引用第一轮选票。
- 条件性否决必须提供重新考虑的条件。
- 决策记录不能保存隐藏思维链字段。

## 协议范围

Protocol 1.0 只仲裁布尔和单选决策。开放问题、多选和排序问题必须先由 Coordinator 转换为明确的单选候选方案；后续协议版本再扩展原生语义。

## 验证结果

32 个单元测试通过，覆盖：

- 数据模型约束
- 不可变性
- 时间与版本校验
- 合法和非法状态转换
- 3:0、2:1、1:1:1
- 弃权、缺失 Agent 和置信度
- 硬性约束
- 重复选票
- 未知与 Restricted 证据
- 版本化 JSON 夹具

## 下一阶段

M2a 已写入 LangGraph Graph API 编排代码；真实 LangGraph 烟测等待依赖可用。M2 使用以下流程：

1. Coordinator 与用户确认 interrupt
2. 证据冻结节点
3. 三人格并行 fan-out/fan-in
4. 第一轮秘密投票
5. 条件路由和一次交叉审查
6. PostgreSQL Checkpointer
7. 公开事件流

LangGraph 只负责编排和恢复；M1 仲裁器继续作为唯一决策规则源。
